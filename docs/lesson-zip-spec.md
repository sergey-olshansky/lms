# Спецификация `lesson.zip` — как читать архив урока (документ для LLM)

Версия схемы: **1.0** · Конвейер: `make_lesson` (whisper.cpp на GPU + GLM-5.3 + GLM-5.3-Flash)

---

## 1. Что это такое

`lesson.zip` — самодостаточный результат разбора учебного видео: транскрипция речи,
смысловая разметка на разделы, ключевые кадры и конспект. В архиве есть всё, кроме
самого видеофайла. Документ ниже описывает состав архива и схему данных; считай его
единственным авторитетным описанием формата.

## 2. Состав архива (жёстко фиксирован)

```
lesson.zip
├── manifest.json     ← источник истины: вся структура, метаданные, ссылки
├── article.md        ← человекочитаемый конспект (производное от manifest)
├── transcript.srt    ← субтитры SubRip (машинная транскрипция с таймкодами)
├── transcript.txt    ← тот же текст сплошником, без таймкодов
└── frames/*.png      ← кадры видео, имена вида NN_MM-SS.png
```

Правила:

- Появление **неизвестных файлов/полей игнорируй** (совместимость вперёд).
- Все пути внутри архива — относительные, с прямым слэшем `/` (POSIX).
- Само видео в архив **не входит**: где его искать — `manifest.source.video`
  (локальный путь или URL исходника на момент генерации).

## 3. Что считать истиной

| Нужны | Бери из | Комментарий |
|---|---|---|
| Структура, таймкоды, теги, кадры | `manifest.json` | Единственный источник истины |
| Готовый текст для отображения | `article.md` | Можно рендерить как есть (markdown, картинки относительные) |
| Дословная речь | `transcript.srt` / `.txt` | Машинный ASR: возможны ошибки и повторы |
| Что нарисовано на доске кадра | `frames[].board_text` | Сырой текст с картинки (OCR-подобный, бывает шум) |

При любом расхождении `manifest.json` приоритетнее `article.md`, а `equations`/`bullets`
из manifest — приоритетнее `board_text` (текст с кадра могли распознать неточно).

## 4. Схема `manifest.json`

```jsonc
{
  "schema_version": "1.0",              // версия этой схемы
  "generated_at": "2026-10-19T23:38:00",// момент сборки, ISO-8601, локальное время
  "source": {
    "video": "C:\\...\\видео.mp4",       // путь или URL исходного видео
    "filename": "видео.mp4",            // имя файла исходника
    "duration_sec": 6171.35,            // длительность, секунды (float)
    "timecode_total": "1:42:51",        // то же в человекочитаемом виде
    "width": 2560, "height": 1440,      // разрешение
    "fps": 60
  },
  "models": {                           // чем сгенерировано (справочно)
    "asr": "whisper.cpp large-v3-turbo (ROCm gfx110X, GPU)",
    "main": "glm-5.3",                  // разметка разделов/тегов/кадров
    "vision": "glm-5.3-flash"           // описания кадров
  },
  "lecture_title": "…",                 // заголовок занятия
  "summary": "…",                       // аннотация 2–4 предложения
  "top_tags": ["#хром", "…"],           // теги всего занятия

  "sections": [                         // ОСНОВНОЙ массив: разделы по порядку времени
    {
      "id": 1,                          // 1..N, по возрастанию
      "title": "…",                     // название раздела
      "start_sec": 0,                   // начало, секунды (int), внутри duration
      "end_sec": 285,                   // конец, секунды; end следующего >= start
      "timecode": "00:00",              // start_sec в формате из п.5
      "tags": ["#ОВР"],                 // теги раздела
      "bullets": ["…"],                 // тезисы раздела (уже вычитены LLM)
      "equations": ["K₂Cr₂O₇ + …"],     // ключевые уравнения, юникод, 1 строка = 1 запись
      "frames": [                       // кадры этого раздела (0–3 шт)
        {
          "file": "frames/01_03-20.png",// путь внутри архива; существует
          "timestamp_sec": 200,         // секунда в исходном видео
          "timecode": "03:20",          // то же человекочитаемо
          "caption": "…",               // короткая подпись (до ~12 слов)
          "board_text": "…"             // текст/формулы, снятые с кадра; может быть ""
        }
      ]
    }
  ],

  "files": {                            // карта стандартных файлов (справочно)
    "article": "article.md",
    "transcript_srt": "transcript.srt",
    "transcript_txt": "transcript.txt",
    "frames_dir": "frames/"
  }
}
```

## 5. Форматы и инварианты (гарантируется конвейером)

**Таймкоды (`timecode`)**: `MM:SS`, если меньше часа, иначе `H:MM:SS`
(например `03:20`, `1:02:10`). Числа с ведущими нулями, кроме старшей группы.

**Гарантии:**

1. `sections` отсортированы по `start_sec`, `id` идут 1..N подряд.
2. Разделы покрывают всё видео: первый начинается с ~0, `end_sec` последнего ≈ `duration_sec`; интервалы не пересекаются (могут стыковаться вплотную).
3. Каждый кадр лежит внутри своей секции: `section.start_sec <= timestamp_sec <= section.end_sec`.
4. Все `frames[].file` реально присутствуют в архиве; суммарно кадров ≤ 24.
5. `tags` — непустые строки, начинаются с `#`, без пробелов внутри.
6. `equations` — юникод: индексы `₂`, заряды/степени `⁺⁶`/`⁻`, стрелки `→`, осадки `↓`, газы `↑`. Химия здесь записана текстом, не LaTeX.
7. `board_text` — «как увидела» vision-модель: возможны обрывки, повторы, потерянные индексы. Использовать как поиск/подсказку, не как эталон.
8. `transcript.srt` — стандартный SubRip. Это «сырой» ASR: в паузах возможны циклические повторы фраз, спецтерминология иногда искажена. Таймкоды srt надёжны.

**Не гарантируется** (не выдумывай при обработке): отсутствие OCR-шума в `board_text`,
идеальная пунктуация transcript, что `article.md` побайтово совпадает с рендером manifest.

## 6. Типовые задачи

**Визуализация урока (сайт):** читай только `manifest.json`; рендер `sections` как
таймлайн/главы, кадры по `file` (относительные пути работают, если разложить архив
как статическую папку), кнопки «перейти к моменту» по `timestamp_sec`.

**Поиск по содержанию:** ищи по `sections[].title`, `bullets`, `tags`, `equations`
и `frames[].board_text`; для дословных цитат — полнотекст по `transcript.txt`.

**Привязка речи к разделу:** субтитль строки srt с интервалом `[a, b]` относятся к
секции, где `start_sec <= a < end_sec`.

**Переход к видео:** `timestamp_sec`/`timecode` — это моменты **исходного видео**
(`source.video`). Для локального плеера: открыть видео и перейти на метку;
для веб-плеера — фрагмент `#t=sec`. Если исходник недоступен, таймкоды всё равно
осмысленны относительно `duration_sec`.
